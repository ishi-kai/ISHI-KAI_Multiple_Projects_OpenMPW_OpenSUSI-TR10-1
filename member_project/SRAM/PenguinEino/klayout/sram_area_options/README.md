# 16×64 SRAM：周辺回路の追加削減候補

2026-09-12追記：受信・アクセス保持段の共用だけを[本体へ反映](../../learning/docs/SEQUENCER_DESIGN.md#13-保持段共有による面積削減)した。以下の面積比較は変更前を基準とする調査記録で、`analyze.py`も明示的に旧構成を生成して再現する。状態判定の簡略化・NAND/NOR化・2段列MUXは採用していない。

2026-09-12。受信段・アクセス保持段の兼用以外にも、既存スタセルの論理の組み替えと、
列選択回路の構成変更に削減候補がある。
ここでは候補を調査し、素子数から面積を再計算した。製品用RTL・回路図・GDSは変更していない。

## 基準と検証範囲

対象は16行×64列、受信11 bit、カウンタ5 bit、1操作19クロック。
面積は既存の周辺見積もりと同じ、スタセルの共有配置幅×55 µmの合計。
単独GDSの外接矩形をそのまま足した値ではない。
配線余白と新たなアナログ素子のレイアウトを含まず、既存の仮のBUF_X4×12の予算は維持する。

[元の回路生成器](../sram_macro_study/macro_model.py)と
[寸法・面積計算](../sram_macro_study/estimate_capacity.py)を読み、
[analyze.py](analyze.py)で再現する。[全数値・論理回路・入力ハッシュ](results.json)。

| 現行1 Kbit構成のブロック | 面積 mm² |
|---|---:|
| 制御部のDFFR×33 | 0.159720 |
| 制御部のMUX2×24 | 0.065340 |
| 制御部のその他の論理 | 0.064130 |
| 行デコーダ | 0.033880 |
| 列デコーダ | 0.101640 |

FFとMUXは制御部面積の約77.8%。ただし列デコーダも大きく、追加の検討対象になる。

## 1. 列デコーダをNANDプリデコード＋NORにする

現在は6 bit列アドレスを3 bitずつに分け、AND3で各8本を作り、
最終AND2×64で組み合わせる。

```text
現在：H = AND3(上位アドレスの条件)
      L = AND3(下位アドレスの条件)
      COL = AND2(H, L)

候補：HB = NAND3(上位アドレスの条件)
      LB = NAND3(下位アドレスの条件)
      COL = NOR2(HB, LB)
```

選択した列だけHIGHになる論理は同じ。列MUX・共通書き込み・SAの接続は変えない。

| 構成 | 面積 mm² |
|---|---:|
| AND3_X1×16＋AND2_X1×64 | 0.101640 |
| NAND3×16＋NOR2×64 | 0.077440 |
| **削減候補** | **0.024200** |

PDKにはこれらの回路図・GDSが存在する。全64アドレスで、出力64本が正しいone-hotになることを確認した。
アドレス切り替え時のグリッチ・実際の遅延・駆動能力は、このBoolean確認には含まない。
最終NOR2は列MUXのNMOSゲート2個を駆動する。PMOSが直列になるので、従来のANDの出力INVと
同じ速度・駆動力とは限らず、実負荷のSPICE確認が次の作業になる。

## 2. 状態デコードから出力までの論理をまとめる

現在の生成器はE0〜E7をそれぞれ完全一致でデコードしてから、ORで動作期間を作る。
例えば1 Kbit構成のWL用D入力は、E3＝count 14とE4＝count 15のOR。
この2値はLSBだけが違うので、次の1条件になる。

```text
WL_D = !C4 & C3 & C2 & C1   // count 14 or 15、C0は不問
```

同様に、書き込み期間13〜16、TRACKの12〜14、結果取り込み17を、
共通条件を共有して直接作る。E0＝11とRX＝count<11も保持する。
E7の観測用だけのデコードは生成しないが、count>=18で0へ戻す動作は維持する。

新しい組み合わせ論理は33スタセル。DFFR×33、MUX2×24はこの候補単独では全て残す。
カウンタ、受信、転送、W保持、SDO保持、外部プロトコル、非同期RESETは変えない。
PREB・WL_EN・WRITE_EN・SAEは引き続きFF出力から取り、状態デコードで直接駆動しない。

| 制御部全体 | 面積 mm² |
|---|---:|
| 現行 | 0.289190 |
| 論理整理後の候補 | 0.266200 |
| **削減候補** | **0.022990** |

32種類のcount符号×Wの2値×WEの2値＝128入力条件を列挙。
次カウンタ5 bit、RX、E0、4個の制御FFのD入力、SDO取り込み許可の計12信号、
1,536比較で元の生成器と一致した。未使用count 19〜31もdon't-careとして省略していない。
これは遅延を含まない論理確認で、FF直後の遷移やセットアップ／ホールドの再検証は必要。

## 3. 行デコーダもNAND＋NORへ変更する

```text
WL = H & L & WL_EN = NOR3(HB, LB, WL_ENB)
```

AND2_X1×8＋AND3_X1×16（0.033880 mm²）を、
NAND2×8＋NOR3×16（0.026620 mm²）へ置換する候補。
**削減候補は0.007260 mm²**。
WL_ENBは既存のWL_EN用DFFの未使用QBから取り出す前提。新しい内部端子・配線が必要。
INVを別に設ける場合は0.0009075 mm²を加える。
全16行×WL_ENの2値を列挙し、論理を確認した。

ただしNOR3のPMOS3段直列で、64列分のアクセスMOSゲート128個とWL配線を駆動することになる。
駆動力を補うために大きくすると削減が相殺される可能性がある。
列側より削減量が小さく、負荷が重いため、優先順位は低い。

## 4. 列MUXを8列×8群の2段選択にする

これは列のアナログ選択経路を変更する候補。
下位3 bitの8本の選択信号で各群の8列から1列ずつ選び、
上位3 bitの8本で、8群のうち1群を共通Y/YBへつなぐ。

```text
各群内のBL/BLB → NMOS選択 → 群の中間線 → NMOS選択 → 共通Y/YB
                  下位3 bit               上位3 bit
```

全64アドレスについて、理想スイッチとして共通線まで導通する列が1つだけであることを確認した。
デコードはAND3_X1×16のまま使えて、最終AND2_X1×64が不要。
**除去できるデジタル面積は0.077440 mm²**。これは純削減量ではない。

- 差動列MUXのNMOSは128個から144個へ増える。
- 中間線8対には、追加プリチャージPMOS16個を設ける案を含めて検討する。
- 下位選択信号1本の負荷はNMOSゲート2個から16個へ増える。駆動力の再評価が必要。
- 読み書きが通る列MUXは1段から2段となる。書き込み時のLOW駆動が弱まり、
  タイミングを長くするだけでは書けない場合もあるため、MUX寸法と書き込み余裕を確認する。
- 中間線の初期化、非選択群の保持、SA入力まで差が届く時間、配線領域を再検証する。

共通の書き込み回路・SAは共有する案。新たなバンクや外部ピンは設けない。
列のNAND＋NOR案と、この最終ANDを除去する案の削減額は重複するため、足してはいけない。
基礎となる列MUXとプリデコードの構成は
[Adam TemanのSRAM講義](https://www.eng.biu.ac.il/temanad/files/2017/02/Lecture-7-SRAM.pdf)を参照。
今回の8×8案はTR-1um向けの検討案で、同資料やPDKから完成回路を移植したものではない。

## 5. FF・MUX自体の専用化

### D入力のMUXをトランスミッションゲートで作る

現在のMUX2は12個のMOSインスタンスを使う回路で、並列倍率m=2の素子も含む。
選択信号と反転信号があれば、2個のCMOSトランスミッションゲート、計4 MOSで
非反転2入力選択ができる。反転信号を作るINVは同じ許可信号のビット群で共有する案がある。
[Weste / Harris, CMOS VLSI Design, 講義1・スライド33](https://cmosvlsi.com/lect1.pdf)。

ただし、このMUX出力自身には論理を再生する出力段がなく、抵抗を通してDFFのD入力を駆動する。
選択信号の切り替え時の競合・電荷共有、前段FFの負荷、D入力の確定時間を確認する。
NMOS単体でHIGHを渡す構成への置換ではない。

対象となる既存MUX面積は現行24個で0.065340 mm²。
受信・保持段を兼用した後は13個で0.0353925 mm²。
新しいTG、反転信号ドライバ、配線を含むGDSをまだ作っていないため、純削減面積は未算定。
MOS数の比率をそのまま面積削減率にはしない。

### 複数FFでクロック位相生成を共有する

現在のDFFR内部は34 MOSインスタンスで、うち6 MOSがCKからCLK/CKBを作る3段のINV。
複数bitのレジスタとして設計し直せば、この位相生成やタップ・電源配置を共有する余地がある。
非同期RESET機能は残せるが、共有ドライバを強くする必要があり、
2つのクロック位相のずれ、ラッチの同時透過、保持時間を含むFFとしての再検証が必要。
独立INVセルの面積×個数をDFF面積から引く計算はしない。現段階で純削減面積は未算定。

### 専用クロックゲートで受信時だけシフトFFへCLKを送る

適切なラッチを備えたクロックゲートを1個設け、受信段11 FFの保持用MUX11個を除去する候補。
除去対象のMUX面積は0.0299475 mm²だが、クロックゲート・バッファ・配線の追加分を引く必要がある。
RXとCLKを単にANDする方法は使わない。
[Teman, Synthesis Part 2, グリッチ防止ラッチ付きクロックゲート](https://www.eng.biu.ac.il/temanad/files/2018/11/Lecture-4-Synthesis-Part-2.pdf)。

これはCLKの分配構成を変える。既存の「全FFを共通CLKで駆動」という内部方針も変更になる。
クロックスキューとシフト段間の保持時間、RESET中・解除時の挙動を再検証する必要があり、
今回の学習方針では後回しを勧める。TG-MUX置換とは同じMUXを対象とするため、削減額を二重計上しない。

## その他の確認結果

- NAND＋INVをANDへまとめる削減は、元の面積見積もりで既に反映されている。
- DFFRを別の既製DFFSへ置換しても共有配置寸法88×55 µmは同じで、面積削減にならない。
- BUF_X4×12、0.021780 mm²は負荷から決めた最終値ではなく予算。見直し余地はあるが、
  大容量化で必要なクロック・PC駆動を確定するまでは削減額として扱わない。
- 独自の小さなFFへ置換したり、W/SDOの保持・RESET機能を外す案は、実装と仕様変更を伴う。
  現行プロトコルを保てる候補を先に検討する。
- 論理合成で候補を探す方法もある。Yosys/ABCは組み合わせ論理の最適化とセル割当てを行えるが、
  正しいセル論理・面積・タイミングの定義が必要。本調査では合成ツールを導入・実行していない。
  [Yosys公式説明](https://yosyshq.readthedocs.io/projects/yosys/en/v0.64/using_yosys/synthesis/abc.html)。

## 推奨する順序と1 Kbitへの見通し

1. 制御論理の整理と列デコーダのNAND＋NOR化を、既存スタセルで確認する。
2. 前に挙げた受信・保持段の兼用を組み合わせ、RTLとトランジスタ回路で再検証する。
3. 必要なら8×8の階層列MUXを比較試作する。アナログ動作が変わるので独立に比較する。
4. さらに必要な場合に、TG-MUXや複数bitの専用FFを検討する。

受信・保持段の兼用（0.0831875 mm²）、制御論理整理（0.022990 mm²）、
列負論理化（0.024200 mm²）、行負論理化（0.007260 mm²）を算術上合算すると、
アレイ＋デジタルは1.16834206→**1.03070456 mm²**。
ただし行NOR3の駆動力は未検証で、まだ統合した実装ではない。
残りは約**0.0493 mm²**しかなく、アナログ周辺・配線・必要な駆動力増強を入れる必要がある。
よって、この数字だけで1 Kbitが収まるとは判断できない。

再計算：

```sh
python3 klayout/sram_area_options/analyze.py
```

今回は制御論理128条件・1,536信号比較、行デコード32条件、列デコード64条件、
階層列MUXの理想接続64条件を確認した。新しい回路のSPICE、DRC/LVS、配置配線は未実施。
