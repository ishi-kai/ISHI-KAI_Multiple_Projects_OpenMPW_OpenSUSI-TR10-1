# Xschemとの同期

- ユーザーの希望により、`.sch`を編集した後は、Xschemで開いている対象回路にも反映する。
- 再読み込み前に `xschem get modified` を確認する。未保存の編集は破棄せず、別ファイルへ退避・差分確認して保持する。
- この環境では `wish` のTk `send xschem {...}` で実行中のXschemに接続できる。対象は `xschem get current_name` で確認し、別の回路を誤って再読み込みしない。
- 未変更の対象回路は `xschem reload` で再読み込みできる。反映後は対象パスと変更内容を確認する。
- 新規タブを開いた後は表示も確認する。`enable_layer`配列が未初期化だと部品・文字が消えて配線だけになる場合がある。欠落時は `set_missing_colors_to_black; xschem enable_layers; xschem redraw` で既存設定を保ちつつ初期化し、画像で表示を確認する。

# KLayoutの単位

- ユーザーの最新指定により、今後作成・更新するGDSと親レイアウトは **DBU = 0.001 µm** に統一する。0.1 µmでは形状やDRCの判定値が丸められるため、以前の0.1 µm指定は撤回済み。
- 既存GDSのDBU変更は実寸を保つ座標変換で行う。`layout.dbu`だけを書き換えて形状の実寸を変えない。
- 変換前のファイルを退避し、グリッド丸めの影響をDRC/LVSで確認する。素子寸法を無断で変更して合わせない。
- 子セルの配置倍率は原則1。異なるDBUでの`Instantiate`インポートにより、意図せず倍率0.5になった事例があるため、取り込み後に倍率と実寸を確認する。
- DBUと配置スナップは別物。dev版の製造格子は0.05 µmなので、セル原点の配置・移動は0.05 µmの整数倍に揃える。DBUは0.001 µmのまま保持する。

# PDKのブランチ

- ユーザー指定により、TR-1um PDKは **devブランチ** を使う。
- 使用先は `/home/ishi-kai/pdk/TR-1um`。devソースは `/home/ishi-kai/src/TR-1um`。インストールし直すと使用先がコピーになることがあるため、symlinkと決めつけず使用中ファイルを確認する。切替時のコミットと旧版の退避先は `design/pdk_active.json` に記録する。
- 旧版でのDRC/LVS結果をdev版での合格として扱わない。PDK切替前から起動中のKLayoutは旧PCellを保持する可能性があるため、保存した作業を新しいプロセスで開いて使う。

# Gitでの履歴管理

- ユーザー指定により、このディレクトリはGitで管理する。
- 意味のある作業の区切り（実装、検証済みの修正など）で適宜コミットする。
- シミュレーションの大容量出力、キャッシュ、退避用の個人設定は追跡しない。回路図、GDS、生成・検証スクリプト、検証結果の要約を追跡する。

# 使用可能なレイアウト領域

- MAC全体は **横1800 µm × 縦1000 µm** の領域内に収める。外接矩形だけでなく、配置座標が領域内であることも検証する。
